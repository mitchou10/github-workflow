# lint-helm.yml

Lints Helm charts with [chart-testing](https://github.com/helm/chart-testing) (`ct lint`), and optionally checks
that the README generated by [helm-docs](https://github.com/norwoodj/helm-docs) is up to date.

```yaml
lint-helm:
  uses: Mitchou10/github-workflow/.github/workflows/lint-helm.yml@v0
  permissions:
    contents: read
  with:
    CHART_DIRS: charts
    LINT_DOCS: true
```

## What `ct lint` checks

- `helm lint` on the chart, once with its default values and once per file `ci/*-values.yaml`;
- YAML style with yamllint;
- `Chart.yaml` against a schema (required fields, types);
- with `CHECK_VERSION_INCREMENT`, that the chart version was bumped;
- with `VALIDATE_MAINTAINERS`, that the maintainers are valid GitHub users.

Chart dependencies are built (`helm dependency build`) before linting. Rendering is checked with the values files
of `ci/`: add one per optional feature (ingress on, persistence on...) to lint the templates behind conditions.

## Where charts are found

chart-testing looks at the **subdirectories** of `CHART_DIRS`. With the default `.`, a chart in `helm/Chart.yaml`
is found. A chart whose `Chart.yaml` is at the repository root is not: move it in a subdirectory, or point
`CHART_DIRS` at the parent of the chart directories (for example `charts` for `charts/app/Chart.yaml`).

## Inputs

| Input | Default | Description |
| --- | --- | --- |
| `CHART_DIRS` | `.` | Comma-separated directories whose subdirectories are charts |
| `CHART_REPOS` | empty | Repositories of the dependencies, comma separated `name=url`. OCI dependencies need none |
| `CT_CONF_PATH` | empty | Your own chart-testing config. When set, `CHART_DIRS`, `CHART_REPOS`, `CHECK_VERSION_INCREMENT` and `VALIDATE_MAINTAINERS` are ignored |
| `ONLY_CHANGED` | `false` | Lint only the charts changed since `TARGET_BRANCH` |
| `TARGET_BRANCH` | empty | Branch to compare with. Empty: the PR base, else the default branch |
| `CHECK_VERSION_INCREMENT` | `false` | Require a chart version bump |
| `VALIDATE_MAINTAINERS` | `false` | Validate `maintainers` in `Chart.yaml` |
| `HELM_VERSION` | `latest` | Helm version |
| `LINT_DOCS` | `false` | Also check the helm-docs README |
| `DOCS_DIR` | `.` | Directory searched for charts by helm-docs |
| `HELM_DOCS_VERSION` | `v1.14.2` | helm-docs version |
| `RUNS_ON` | `["ubuntu-24.04"]` | Runner labels, as a JSON array |

By default **all** charts are linted (`ct lint --all`), which is predictable and quick for a few charts. Use
`ONLY_CHANGED` in a repository with many charts.

## Defaults worth knowing

- `CHECK_VERSION_INCREMENT` is off. When the chart version is bumped by the release pipeline (for example by a
  job that follows release-please) and not by hand in each pull request, requiring a bump would fail every PR.
- `VALIDATE_MAINTAINERS` is off: it calls GitHub to check that each maintainer is a real user, and most
  application charts do not list maintainers.

## helm-docs

With `LINT_DOCS`, the job runs helm-docs on the repository and **fails if that changes any file**: the committed
README no longer matches the chart values or its template. Fix it locally:

```bash
docker run --rm -v "$PWD:/helm-docs" -u "$(id -u)" jnorwood/helm-docs:v1.14.2
```

then commit the README. Document values with `# -- description` comments in `values.yaml`.

## Your own chart-testing configuration

`CT_CONF_PATH` takes a `ct.yaml`, for example:

```yaml
chart-dirs:
  - .
chart-repos:
  - cnpg=https://cloudnative-pg.github.io/charts
validate-maintainers: false
check-version-increment: false
target-branch: main
```

## Limits

This workflow lints; it does not install the chart in a cluster (`ct install`). Add a job with `kind` for that.
